## 1. 目标与设计原则

1. **状态可见**：轮到谁、当前阶段、可行动作、剩余资源，不滚动、不点开就能看到。
2. **身份可辨**：自己 / 对手 / 观战三种视角一眼区分；自己的牌堆、手牌、场上、弃牌各有稳定位置与颜色。
3. **行动可跟随**：任何行动都有即时反馈（高亮、浮字、脉冲、日志置顶），玩家不会“刚才发生了什么”。
4. **元素用堆叠，不用“符号+数字”**：水/风/火/土以可数的小圆片（pip）堆叠呈现；超过 5 个显示“5 + n”折叠。
5. **少即是多**：默认界面只留决策必需信息，卡牌详情按需展开（点击/长按/悬浮）。
6. **敢于重构**：Panel 拆成 `board/`、`cards/`、`energy/`、`modals/` 组件；样式全部走设计令牌，不堆 `ss-` 例外。
7. **不碰后端**：只消费 `SeasonsGameView` 既有字段；确需新字段先改协议 + 服务端，再回来做 UI。

### 1.1 现有问题清单（2026-11-25 评估）

- 能量是 `图标 + 数字`，看不出“几个”；元素选择按钮只有文字。
- 手牌、牌堆、场上牌都用同一个 `CardChip`，尺寸/位置差异小。
- 对手区与自己的区结构相同，仅标题不同；多人局难分辨。
- 无任何动画；日志是唯一反馈，且只有 8 条、无高亮。
- 费用/可支付性没有提示：点了才知道付不起。
- 卡牌详情（完整描述、效果）不可查看。
- 移动端只是缩小尺寸，触控目标偏小。

## 2. 架构与约束

- 入口：`apps/web/src/games/seasons/index.tsx`（插件 meta）→ `Panel.tsx`（牌桌）→ `ChoiceModal.tsx`（10 种选择）。
- 样式：`styles.css` 单文件，当前 355 行；本计划拆成 `styles/` 下的 `tokens.css`、`board.css`、`cards.css`、`modals.css`（Vite 支持 CSS `@import`）。
- 卡图：`art.ts` 的 `cardArt/dieArt/elementArt`（webp，骰/元素内联 data URI）。
- 可用字段：`SeasonsGameView`（phase/month/year/season/dice/players/deckCount/discardCount/pendingChoice/pendingQueueCount/myTurn/log/result…）、`SeasonsPlayerView`（hand/draftHand/drafted/played/energies/crystals/gauge/maxEnergy/badgeDraw…）。
- 无新依赖：纯 CSS + React 18/19；动画用 CSS transition/animation，不引 framer-motion。
- 显卡/机器约束：构建机 2GB 内存，`web build` 需 `NODE_OPTIONS=--max-old-space-size=512`，见 `seasons-migration.md`。
- 验证脚本：`apps/web/scripts/seasons-render-smoke.mjs`（1149+ 次 SSR 渲染 + 11 种弹窗），任何布局重构后必须过。

## 3. 设计系统（F1 落地）

### 3.1 令牌（`styles/tokens.css`）

- 色板：`--ss-bg`（深夜蓝绿）、`--ss-surface`、`--ss-surface-2`、`--ss-line`、`--ss-text`、`--ss-muted`、`--ss-accent`（金）。
- 元素色：水 `#4aa3df`、风 `#63c9a8`、火 `#e2704a`、土 `#b08a5a`（附深色描边，保证对比度）。
- 玩家色：自己 = 金色描边 + 高亮底；对手 1/2/3 = 蓝/紫/绿侧条；观战 = 中性灰。
- 间距：4 的倍数（4/8/12/16/24/32）；圆角 6/10/16；阴影两级。
- 字体：系统 UI；数字用等宽 `font-variant-numeric: tabular-nums`。
- 尺寸：卡牌 `--ss-card-w: 92px`（桌面）/ 64px（窄屏）；骰 56px；pip 10px。

### 3.2 元素堆叠组件（`energy/ElementStack.tsx`）

- 单个元素：竖向/横向堆叠 pip（最多 5 个），第 6 个起显示 `+n` 角标；hover/长按显示精确数量。
- 组合元素：`ElementRow` 按 水→风→火→土 固定顺序渲染，空元素显示淡色“0”占位（仅自己区）。
- 使用场合：储备区、卡牌费用、骰面奖励、支付弹窗、徽章换能量、护符选择、`element_alloc`/`element_pick`/`element_multi` 弹窗。
- 规则：**任何“元素+数字”文本都替换为堆叠**；日志与 title 仍保留文字（可读性/无障碍）。

### 3.3 卡牌组件（`cards/Card.tsx`）

- 三种形态：`CardTile`（手牌/牌堆正面）、`CardBack`（牌堆背面，带数量）、`CardMini`（场上/弃牌，横向小卡）。
- 手牌：大卡、可点击抬升 + 金色描边；牌堆：背面堆叠 + 数量角标 + “牌堆”标签；场上：横向小卡，带激活状态徽标；弃牌：灰化背面 + 数量。
- 卡面信息：左上费用 pip、右上分数、底部名称；完整描述点击后在 `CardDetail` 浮层查看。

## 4. 分阶段计划

### F1 视觉系统与元素堆叠（1–2 夜）
- F1.1 设计令牌 + 元素堆叠组件（ElementStack/ElementRow/Pip）。
- F1.2 储备区、支付弹窗、徽章、护符、三种元素选择弹窗全部改用堆叠。
- F1.3 卡牌组件拆分为 CardTile/CardBack/CardMini；手牌、牌堆、场上、弃牌视觉区分。
- 验收：`web build` + `smoke` 通过；桌面/窄屏截图自检；元素数量 0–9 的渲染均正确。

### F2 牌桌布局与身份区分（2–3 夜）
- F2.1 桌面布局：顶部状态条（阶段/年月/牌堆弃牌/回合倒计时）→ 中央骰池与对手区 → 底部自己区与手牌。
- F2.2 自己区固定为“我的牌桌”：自己的牌堆/弃牌/徽章/等级/水晶/储备集中在底部；对手区紧凑化（头像色条 + 水晶/等级/手牌数 + 场上小卡）。
- F2.3 3–4 人局对手区网格；当前行动者高亮描边 + “行动中”标签。
- 验收：观战/2/3/4 人四种视角渲染不串位；对手手牌只显示背面数量。

### F3 行动反馈与动效（2–3 夜）
- F3.1 事件高亮：最近一次召唤/激活/转化/换季在对应卡/玩家上做 600ms 金色脉冲；日志新条目淡入并置顶。
- F3.2 资源浮字：水晶/能量/召唤等级变化时在对应区域浮 `+2`/`-1`（CSS keyframes，`prefers-reduced-motion` 关闭）。
- F3.3 回合提示：轮到自己时顶部条变色 + 轻微脉冲；他人行动时显示“座位 X 行动中”。
- F3.4 骰子选骰反馈：选中的骰翻面/上浮；新月份骰池入场动画。
- 验收：动画不阻塞点击；减少动效模式下无动画；smoke 不因动画报错。

### F4 操作流程与可支付性（2–3 夜）
- F4.1 召唤可用性：手牌上的费用 pip 按当前储备高亮可付/不可付；不可付置灰并 title 说明缺什么。
- F4.2 召唤确认条：点击手牌后在底部展开“召唤 名称 · 费用 · 效果摘要 · 确认/取消”，避免误触。
- F4.3 激活提示：场上可激活卡显示“可激活”角标；点击后展示本次激活收益再确认。
- F4.4 转化与结束回合：转化按钮展示“元素 → 水晶数”；结束回合前若还能行动给出轻提示（可关闭）。
- F4.5 组牌体验：已选 3 张的年份预览、撤销、拖动排序（可选）。
- 验收：所有动作从点击到提交 ≤2 步；误触可取消；键盘 Enter/Esc 可用。

### F5 卡牌详情与信息层级（1–2 夜）
- F5.1 `CardDetail` 浮层：大图 + 完整描述 + 费用/分数 + 效果说明（来自卡表 desc）。
- F5.2 长按/悬浮/点击三种触发；移动端长按 300ms。
- F5.3 阶段说明折叠面板（轮抽/组牌/行动规则摘要）。
- 验收：所有 50 张卡均可打开详情；浮层不遮挡当前操作按钮。

### F6 移动端与可达性（1–2 夜）
- F6.1 断点：≤900px 两栏变单栏；≤600px 手牌横向滚动 + 底部固定操作条。
- F6.2 触控目标 ≥44px；字号下限 12px；对比度 ≥4.5:1。
- F6.3 ARIA：日志 `aria-live="polite"`、弹窗 focus trap、骰子/卡牌 `aria-label`。
- 验收：手机宽度 390px 渲染不溢出；键盘可完成一局的关键动作。

### F7 打磨与性能（持续）
- F7.1 事件动画队列化（避免同帧多动画打架）。
- F7.2 卡图懒加载 + `loading="lazy"`；Panel 子组件 memo 化。
- F7.3 新手引导：首局 3 步提示（轮抽/组牌/行动），可跳过。
- F7.4 音效（可选，默认关）。
- 验收：首屏渲染 <100ms（本地），smoke 覆盖新增组件。

### F8 结算与复盘（持续）

- **F8.1 终局结算表**：名次（同分并列）、座位色、总分、分数构成条（水晶/卡牌/效果）、逐项明细（含手牌与徽章惩罚）、场上张数与剩余能量。
- **F8.2 行动提示**（待做）：回合开始时列出「现在能做什么」（可召唤几张、可激活哪些、是否可晶化、该选骰/该结束）。
- **F8.3a 复盘日志**：全量日志按类别筛选（行动/轮抽组牌/季节/计分）、展开全部并自动滚到最新。
- **F8.3b 逐步回放**（待做，依赖后端状态快照）：按 log 逐步还原盘面，需要引擎侧支持，先记待确认。

### F9 观战与多人视角（持续）

- **F9.1 观战视图**：观战者看到所有座位的公开面板（非 compact）、顶部「观战」标记，明确「看不到任何人的手牌」。
- **F9.2 行动跟随**（✅ 2026-11-26）：观战时自动滚动到当前行动者/选骰者，手动滚动暂停、可恢复。

## 7. 决策与日志

### 7.1 设计决策
- **元素堆叠而不是数字**：可数性优先；超过 5 个折叠为 `5 + n`，避免宽度爆炸。
- **自己/对手分色**：自己金色、对手按座位蓝/紫/绿；不只靠文字标签。
- **动画克制**：只做“刚刚发生”的高亮与浮字，不做持续闪烁；减少动效模式下全部关闭。
- **组件拆分而非单文件膨胀**：Panel 目标 <400 行，子组件各自独立。

## 8. 双人协作规则（2026-11-25 起）

用户安排了一位 GPT 协作者共同开发，长期优化，没有终点。约定：

1. **文档通道**：我维护 `TO_GPT.md`（做了什么 / 下一步 / 待对方决定的问题），对方维护 `TO_DS.md`；两个文件都在 `bgx` 与 `bgx_seasons` 根目录。
2. **开工顺序**：两个仓库都 `git pull --rebase` → 读 `TO_DS.md`（如果存在）→ 读本文件 §0/§5/§7 → `git log --oneline -10` → 确认没有别人未推送的改动 → 再做。跨主机只能靠推送交流，详见 `TO_GPT.md` §7。
3. **收工顺序**：跑验证 → 更新本文件 §0/§5/§7 + `docs/games/seasons-migration.md` §12（涉及引擎时）→ 更新 `TO_GPT.md`（最近改动/下一步/给对方的请求）→ 两个仓库提交推送。
4. **分工原则**：前端体验归我主责；对方若改引擎/协议，需在 `TO_DS.md` 写明动机与影响面。任何一方改完都必须过 server test + web build + smoke。
5. **部署**：保持最新可部署；用户说「部署」时执行，不擅自改线上。
6. **冲突处理**：以用户裁定 > 旧引擎卡面 > 现有实现为优先级；不确定写「待确认」，不猜。
7. **长期 backlog**：见 `TO_GPT.md` §6；每次完成一项就从 backlog 或用户反馈里取下一项，不空转。
